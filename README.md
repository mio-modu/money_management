# 머니가드 (MoneyGuard)

**가계부가 아니다.** 돈이 새는 지점을 스스로 찾아내 경고하고,
그래서 지금 뭘 해야 하는지까지 말하는 **개인 재정 에이전트**다.

입력은 최소로, 판정·경고·제안은 전부 자동으로. 이 한 줄이 설계의 전부다.

```
금액 → 카테고리 탭 → 끝.   그 다음은 앱이 알아서 판정한다.
```

---

## 왜 또 가계부인가

기록 앱은 두 가지로 죽는다. **입력이 귀찮아서**, 그리고 **기록해 봐야 아무 말도 안 해 줘서**.

| 보통 가계부 | 머니가드 |
|---|---|
| 항목 7~8개를 채워야 저장된다 | **금액·카테고리 2개**면 끝. 나머지는 전부 선택 |
| "식비가 많습니다" | "식비 12만원 초과. 이번 주 외식 2회를 1회로 줄이면 복구된다" + `[예산 조정]` |
| 월말에 그래프를 보여 준다 | 입력할 때마다, 그리고 매일 자정에 **규칙 15종**이 돌아간다 |
| 경고만 쌓인다 | 칭찬:경고를 **1:2 이상**으로 유지한다. 경고만 쌓이면 앱을 안 열게 되니까 |

## 지금 돌아가는 것

| 화면 | 하는 일 |
|---|---|
| **홈** | 숫자 딱 3개(순자산 · 이번 달 쓸 수 있는 돈 · 재정 건강 점수) + 에이전트 브리핑 3장 |
| **빠른 입력** | 숫자패드 → 카테고리 아이콘 탭 → 저장. 가맹점이 같으면 카테고리를 자동 추론 |
| **현금흐름** | 6개월 수입/지출, 고정 vs 변동, **고정지출 비중** 경고, 불규칙 수입 안전 예산 |
| **지출 분석** | 등급 트리맵, 전월 대비 TOP5, 요일·시간대 패턴, **필수/선택/낭비 6개월 추이** |
| **예산** | 카테고리별 소진 속도(경과율 기준선 포함), 최근 3개월 중앙값 자동 제안, 이월 |
| **월간 결산** | 한 줄 요약 · 순자산 추이 · TOP5 · 등급 변화 · 다음 달 예산 |
| **구독 관리** | **연간 환산 합계**, 좀비 자동 태깅, 해지 시 절감액, 끊을 순서 시뮬레이션 |
| **자산 · 부채** | 순자산 추이, 비상자금 개월수, 계좌/자산/부채 인라인 수정 |
| **상환 시뮬레이터** | **눈덩이 vs 눈사태** — 몇 달 단축되고 이자 얼마 아끼는지 숫자로 |
| **사업 지갑** | **세금 떼고 실제 내 돈**, 부가세·종소세 적립, 미수금 지연 일수 |
| **목표** | 월 필요 저축액 역산 → "구독 3개를 끊으면 29개월 당겨진다"로 연결 |
| **재정 건강 점수** | 0~100 점수를 **6개 항목으로 펼쳐** 근거와 다음 행동까지 |
| **루틴** | 일·주·월·분기·연간 체크리스트 + 지금 봐야 할 실제 숫자 |
| **알림 기록** | 에이전트가 남긴 경고·제안·칭찬 전체. 같은 상황은 다시 쌓이지 않는다 |
| **설정** | 세율 · 규칙 15종 on/off와 임계값 · PIN 잠금 · 알림 · 더미 데이터 |

## 에이전트 규칙 엔진

`lib/agent/rules.ts` 에 선언형으로 적혀 있다. 거래를 저장할 때와 매일 자정에 평가된다.

### 누수 탐지
| 규칙 | 잡아내는 것 |
|---|---|
| `ZOMBIE_SUB` | 60일 넘게 안 쓴 구독 → 해지 시 **연간 절감액**을 바로 계산해 보여 준다 |
| `PRICE_CREEP` | 정기결제 금액 인상 → 인상률과 연간 추가 부담 |
| `DUPLICATE_SERVICE` | 같은 카테고리 구독 2개 이상 → 만족도 최하위부터 통합 제안 |
| `SMALL_LEAK` | 1만원 이하 결제 월 15건 초과 → **합계 금액**으로 충격을 전달 |
| `IMPULSE_PATTERN` | 22시~새벽 2시 결제 월 3건 초과 |
| `CATEGORY_SPIKE` | 3개월 평균 대비 150% 초과 |

### 위험 신호
`BUDGET_PACE` 예산 소진이 날짜보다 20%p 빠름 · `FIXED_RATIO_HIGH` 고정지출 > 수입의 50% ·
`EMERGENCY_FUND_LOW` 현금성 자산 < 월지출×3 · `HIGH_INTEREST_DEBT` 이자율 15% 이상 ·
`TAX_UNRESERVED` 세금 적립 부족 · `INCOME_DROP` 최근 3개월 수입 30% 이상 감소

### 긍정 강화
`STREAK` 무지출일 연속 · `UNDER_BUDGET` 낭비 등급 지출 감소 · `NET_WORTH_UP` 순자산 신고점

> **모든 경고는 "그래서 뭘 해야 하는지" 한 문장과 실행 버튼을 달고 나온다.**
> 그 문장을 못 쓰는 규칙은 규칙이 아니다.

## 바로 돌려 보기

```bash
npm install
npm run dev      # http://localhost:3000
```

**환경변수 없이 그대로 돈다.** 키가 없으면 데이터는 브라우저 안(localStorage)에만 저장되고
서버로 아무것도 나가지 않는다. 설정 → 데이터 → **더미 데이터 생성**을 누르면
6개월치 거래 440여 건이 들어간다.

```bash
npm run seed              # 규칙 엔진이 무엇을 잡아내는지 콘솔로 확인
npm run seed -- --json    # 앱에서 "가져오기"로 넣을 JSON
npm run seed -- --sql     # Supabase 에 바로 붓는 INSERT 문
```

더미 데이터에는 **좀비 구독 3개 · 가격 인상 · OTT 중복 · 심야 결제 · 고금리 카드론 ·
세금 미적립 · 수입 39% 감소**를 일부러 심어 뒀다. 규칙 15종이 전부 발동한다.

### Supabase 를 붙이려면

```bash
cp .env.example .env.local   # URL 과 anon key 를 채운다
```

`supabase/migrations/0001_init.sql` 을 SQL Editor 에서 실행한다.
14개 테이블 전부 RLS 가 걸려 있고 `user_id = auth.uid()` 인 행만 읽고 쓴다.
1인 사용을 전제로 하지만 구조는 처음부터 멀티유저다.

## 설계에서 양보하지 않은 것

- **입력 항목을 늘리지 않는다.** 필수는 금액·카테고리 2개뿐이다.
- **투자 종목 추천, 수익률 예측은 넣지 않는다.** 관리 도구이지 투자 도구가 아니다.
- **한 화면에 경고 3개를 넘기지 않는다.** 우선순위 상위 3개만 노출한다.
- **빨강은 실제 위험에만.** 숫자는 크게, 색은 적게.
- 금액은 `1,250,000원 (125만)` 처럼 **콤마와 만원 축약을 병행**한다.
- 빈 화면에도 **다음 행동**을 적는다.

## 구조

```
app/              화면 (Next.js App Router)
components/       UI. 아이콘도 직접 그렸다 — 번들을 가볍게, 선 굵기를 전체에서 똑같이
lib/
  agent/rules.ts  ★ 규칙 15종. 선언형
  agent/engine.ts 평가 · 중복 제거 · 칭찬:경고 비율 유지
  finance/        순자산 · 예산 · 안전 예산 · 건강 점수 · 부채 시뮬 · 세금
  data/           저장소 교체 지점 (로컬 ↔ Supabase, 같은 인터페이스)
  demo.ts         더미 데이터 — 규칙이 발동하도록 "새는 지점"을 심어 둔다

```

### 차트는 눈대중으로 색을 고르지 않았다

색맹 분리도(ΔE)와 표면 대비를 검증기로 돌려 **통과한 조합만** 썼다.
다크/라이트는 밝기를 뒤집은 게 아니라 각각 따로 고른 값이다.

- 수입 `#199e70` · 지출 `#3987e5` — 인접 쌍 CVD ΔE 19.6, 일반 시야 20.9 (기준 8 / 15)
- 필수 `#3987e5` · 선택 `#c98500` · 낭비 `#d55181` — 전체 쌍 CVD ΔE 13.2, 일반 13.2↑
- 2계열 이상이면 범례를 항상 붙이고, 표로도 같은 숫자를 볼 수 있게 했다. 색만으로 읽게 두지 않는다.

### 불규칙 수입을 전제로 설계했다

프리랜서·1인 사업자는 월급쟁이와 계산이 다르다.

- 안전 예산은 **최근 6개월 수입의 중앙값** 기준이다. 평균은 한 번의 큰 입금에 끌려간다.
  단, 최근 3개월이 더 낮으면 **낮은 쪽**을 쓴다. 수입이 꺾인 직후에는 6개월 중앙값이
  아직 좋았던 달에 걸려 있어서 "안전"하지 않다.
- 예산은 **변동·개인 지출**에만 잡는다. 월세·보험 같은 고정비는 예산을 잡아 봐야
  지켰다/못 지켰다가 의미 없다.
- 사업 수입은 **들어온 순간 세금 몫을 뗀 뒤** "실제 내 돈"으로 보여 준다.
- 고정지출 비중은 **직전 3개월 완결 데이터**로 계산한다. 월 중에 이번 달 숫자를 쓰면
  아직 안 나간 고정비 때문에 비중이 낮게 보인다.

## 홈 화면에 설치해서 쓴다

`manifest.webmanifest` + 서비스 워커가 들어 있다. 모바일 브라우저에서 **홈 화면에 추가**하면
주소창 없이 앱처럼 열리고, 네트워크가 끊겨도 입력 화면은 캐시에서 뜬다.
바로가기로 "지출 입력"과 "오늘의 브리핑"을 길게 눌러 바로 열 수 있다.

**규칙 평가 시점**

| 환경 | 언제 평가되나 |
|---|---|
| 로컬 모드 | 거래를 저장할 때, 앱을 열 때, 열어 둔 채 자정이 지날 때 |
| Supabase + 서비스 키 | 위에 더해 **매일 자정 cron** (`/api/cron/evaluate`, `vercel.json` 에 등록) |

알림은 "앱을 열었을 때 가장 급한 경고 하나"까지다. 앱이 닫혀 있을 때 오는 진짜 푸시는
푸시 서버와 VAPID 키가 필요해서 넣지 않았다 — 없는 기능을 있는 척하지 않는다.

## 배포

```bash
vercel          # 환경변수 없이도 그대로 뜬다 (로컬 모드)
```

Supabase 를 붙이려면 프로젝트 환경변수에 `NEXT_PUBLIC_SUPABASE_URL`,
`NEXT_PUBLIC_SUPABASE_ANON_KEY` 를 넣고 마이그레이션을 실행한다.
서버 cron 까지 돌리려면 `SUPABASE_SERVICE_ROLE_KEY` 와 `CRON_SECRET` 을 추가한다.
서비스 키는 **절대 `NEXT_PUBLIC_` 접두사를 붙이지 않는다** — 브라우저로 나가면 RLS 가 무의미해진다.
